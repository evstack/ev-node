# v1.3.0 release preparation

Status: preparation only. No release tags or GitHub releases have been created by this work.

Prepared from `main` at `aa588d388131fc2360abe489a0285fdcabc3a327` on 2026-10-26. Recheck the final candidate after merging release preparation and dependency updates.

## Release scope

The baseline is the existing `v1.2.3` tag. Version `v1.3.0` adds optional client-side signed Celestia blob submissions and includes fixes for sequencer recovery, DA subscriber lifecycle, pruning, finalization during DA backlog, and execution payload decoding.

GitHub currently marks `v1.1.4` as the latest published release. Tags `v1.2.0` through `v1.2.3` already exist, and the `v1.2.1` GitHub release is a draft. Operators upgrading from `v1.1.4` must also review the intervening changelog, including proposer key rotation and removal of `evgrpc` and `execution/grpc`. Do not carry the draft's unverified migration claims into the final release notes.

## Verification evidence

At the baseline SHA, [CI](https://github.com/evstack/ev-node/actions/runs/40212858711) passed unit, integration, EVM execution, system E2E, Docker E2E, signed submission E2E, builds, module tidy checks, and Go/document/configuration lint jobs.

The upgrade and compatibility jobs also passed, but their defaults use mutable `main` images. These results do not establish compatibility with a released version. `test/docker-e2e/upgrade_test.go` hardcodes its starting image to `main`; the compatibility suite allows `SEQUENCER_EVM_IMAGE_TAG` and `FULLNODE_EVM_IMAGE_TAG` overrides.

[Rust Clippy](https://github.com/evstack/ev-node/actions/runs/40212858694) failed with 11 `double_must_use` errors in generated service code. [Benchmarks](https://github.com/evstack/ev-node/actions/runs/40212858664) failed in State Pressure Benchmark; logs include RPC HTTP 429 connection-limit errors. The benchmark root cause remains unresolved. Rust CI Status jobs also failed.

## Proposed publication order

Go modules have independent versions. Preserve `core/v1.1.0` unless its public API changes; the diff since `v1.2.3` contains only comments and test modernizations in core.

1. Merge root release preparation and publish root `v1.3.0` after the gates pass.
2. Update `execution/evm` and `da/celestia` to require root `v1.3.0`. Remove the temporary root replacement from `da/celestia`, run module tidy and tests, and publish proposed tags `execution/evm/v1.1.2` and `da/celestia/v0.1.0`. Confirm version choices against each module's full diff before publishing.
3. Update app requirements to root `v1.3.0`, the released EVM execution module, and the released Celestia module. Remove temporary local root and Celestia replacements from app modules. Keep the Celestia dependency replacements documented in `da/celestia/doc.go`; Go does not inherit those from dependencies. Tidy and verify builds with `GOWORK=off` outside the source checkout.
4. Publish app tags, proposed `apps/evm/v1.3.0` and `apps/testapp/v1.3.0`, once their pinned dependency graph is verified. App-tag pushes trigger `.github/workflows/release-apps.yml`, publishing versioned GHCR images and updating `latest`. Review this operational effect before pushing tags.
5. Verify versioned images resolve to the intended app commits and pass release smoke tests. Decide whether loadgen needs a separate app release; do not list an image that has not been built.
6. Generate a GitHub draft for root `v1.3.0`, review its exact source SHA, notes, image list, and upgrade claims, then publish. The current draft workflow checks out the dispatch ref, so run it at the intended release ref. Root and app tags may refer to different commits because app pins follow root publication.

## Draft release summary

ev-node v1.3.0 adds optional local signing of Celestia PayForBlobs submissions over consensus gRPC, allowing aggregators and force-inclusion servers to use DA endpoints that cannot sign. The feature is disabled by default. Configure and fund a signer before enabling `da.tx_signer`.

This release also fixes sequencer recovery safety checks, concurrent DA subscriber lifecycle transitions, state snapshot pruning, DA-backlog finalization retries, canceled height waiters, and execution payload decoding.

Tested release-to-release upgrade paths: pending. See the [changelog](https://github.com/evstack/ev-node/blob/main/CHANGELOG.md#v130) for details, and review the v1.2.x changes when upgrading from v1.1.x.
